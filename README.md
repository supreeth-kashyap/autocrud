# AutoCRUD

AutoCRUD is a powerful Python library that automatically generates REST APIs from your existing database models and functions. You can instantly create a secure, production-ready API with just a few lines of configuration. It uses FastAPI, SQLAlchemy, and Pydantic to provide a modern, fast, and well-documented API.

## Installation

To get started, you can install `autocrud` using pip:

```bash
pip install autocrud
```

## Quickstart: An API From an Existing Database

No Python models needed. Point `autocrud` at a database and serve it:

```bash
autocrud init --database sqlite:///app.db && autocrud serve
```

`init --database` reflects the database's tables and writes an `autocrud.yml` that exposes each one **read-only** (`list` and `get`, or `list` alone for a table without a single-column primary key), with columns whose names look sensitive already in `exclude_fields`. Review `expose.models`, add `create`, `update` or `delete` where you want writes, and restart `serve`.

To see what is in a database before writing the config yourself:

```bash
autocrud inspect --database sqlite:///app.db   # or: autocrud inspect (uses the config's database)
```

```
authors (primary key: id)
  id: INTEGER, primary key
  name: TEXT, not null
  email: TEXT
events (no primary key: list only)
  kind: TEXT, not null
  note: TEXT
```

When the config has no `models_module`, AutoCRUD reflects the database at `database` with SQLAlchemy's automap, and `expose.models` names **tables** rather than classes:

```yaml
database: sqlite:///app.db
expose:
  models:
    authors: [list, get, create, update, delete]
    events: [list]
security:
  api_key: <generated by autocrud init>
```

- An unknown table name is reported with the list of tables in the database.
- A table without a primary key (or a many-to-many association table) is served with `list` only, ordered by all of its columns; other operations listed for it are skipped with a warning at startup.
- `expose.models: "*"` exposes every table read-only (`list`, plus `get` where there is a single-column primary key). Because that includes tables added later, it also needs `expose.allow_all_tables: true`, and the startup log names every table it serves. Sensitive-looking columns are warned about as usual; to exclude them, list the tables explicitly.

## Quickstart Guide: Your SQLAlchemy Models

Follow these steps to serve the models from your own Python code.

### 1. Initialize Your Project

After installing the library, navigate to your project's root directory in your terminal and run the `init` command:

```bash
autocrud init
```

This command creates a commented `autocrud.yml` file in your directory with a randomly generated API key. This file is where you will configure your API.

### 2. Edit Your Config

Next, open `autocrud.yml`, point `models_module` at the module that defines your SQLAlchemy models, and list the models you want to expose.

Here is an example configuration:

```yaml
database: sqlite:///dev.db
models_module: myapp.models
expose:
  models:
    User:
      operations: [list, get, update]
      exclude_fields: [password_hash]
    Order: [list, get]
  functions:
    - get_active_users
security:
  api_key: <generated by autocrud init>
rate_limit:
  requests_per_minute: 100
```

- **`database`**: Your SQLAlchemy database connection string. AutoCRUD does not create tables; they must already exist.
- **`models_module`** (optional): The dotted import path of the module that defines your SQLAlchemy mapped classes, importable from the directory you run `autocrud` in (e.g. `myapp.models`, or `examples.demo_app.models` for the bundled example). Leave it out to reflect the database's tables instead (see the quickstart above).
- **`functions_module`** (optional): The dotted import path of the module that defines the functions under `expose.functions`. Defaults to `models_module`.
- **`expose.models`**: The mapped classes to expose, by class name (or tables, by table name, without `models_module`). For each model, list the CRUD operations (`list`, `get`, `create`, `update`, `delete`) to enable, or use a mapping with `operations` and an optional `exclude_fields` list of column names to leave out of every request and response schema. Excluding a column that `create` needs (not nullable, no default) is an error.
- **`expose.functions`**: A list of regular Python functions you want to expose as secure GET endpoints at `/functions/{name}`.
- **`security.api_key`**: The secret key that clients must provide in the `X-API-Key` header to access the API. The `AUTOCRUD_API_KEY` environment variable, when set, overrides it, so you can keep the key out of the file.
- **`rate_limit.requests_per_minute`** (optional): How many requests each client IP may make in any 60-second window. Leave it out for no limit.

The config is checked when you run `serve` or `publish`; a missing key, an unknown operation or an unknown model is reported with a short error message. An unknown model name lists the mapped classes available in `models_module`. The server refuses to start if no API key is configured, or if the key is `test-secret` (the key earlier versions of the example config shipped with).

### Exposed Functions

Each name under `expose.functions` is imported from `functions_module` and served at `GET /functions/{name}`, behind the same API key and rate limit as the CRUD routes. The function's parameters become query parameters, typed from its annotations (unannotated parameters are strings) and required unless they have a default. The return value is sent as JSON. For example, the bundled `greet(name: str, times: int = 1)` is called with `GET /functions/greet?name=Ada&times=2`, and `times=many` returns 422.

### Generated Routes

Only the operations you list for a model are registered. For a model whose table is `users`:

| Operation | Route | Notes |
|-----------|-------|-------|
| `list` | `GET /users` | `limit` (default 100, max 1000) and `offset` query parameters, ordered by primary key |
| `get` | `GET /users/{pk}` | 404 if the row does not exist |
| `create` | `POST /users` | Returns 201 with the created row |
| `update` | `PATCH /users/{pk}` | Partial update; 404 if the row does not exist |
| `delete` | `DELETE /users/{pk}` | Returns 204; 404 if the row does not exist |

Request and response bodies use Pydantic schemas built from your columns' Python types: `UserRead` (every column not in `exclude_fields`), `UserCreate` (no autoincrement primary key; nullable or defaulted columns optional) and `UserUpdate` (every non-key column optional). A change that violates a database constraint returns 409. Each request gets its own database session, committed on success and rolled back on error.

### 3. Serve Your API

Start a development server:

```bash
autocrud serve
```

Options: `--config PATH` (default `autocrud.yml`), `--host` (default `127.0.0.1`), `--port` (default `8000`) and `--reload`. The command prints the URL of the interactive docs.

Your API is now live and ready to accept requests!

### 4. Publish (Optional)

To scaffold a deployable application, use the `publish` command:

```bash
autocrud publish
```

This creates a `main.py` that loads your `--config` file, a `Dockerfile` based on `python:3.12-slim`, and a `requirements.txt` pinned to your installed `autocrud` version. If any of these files already exist, `publish` asks before overwriting them; pass `--force` to overwrite without asking.

## Interactive API Documentation

Once your application is running, `autocrud` automatically generates interactive API documentation for you. You can access it by navigating to these URLs in your browser:

- **Swagger UI**: `http://127.0.0.1:8000/docs`
- **ReDoc**: `http://127.0.0.1:8000/redoc`

You will see all your configured endpoints, their expected inputs, and their responses. You can even try them out directly from the browser.

## Security Considerations

- **API Key**: Your API is protected by an API key. Never expose this key in public client-side code. All requests must include the `X-API-Key` header with your secret key; a missing or wrong key gets 401. The key is read once at startup (from `AUTOCRUD_API_KEY`, else `security.api_key`) and compared in constant time.
- **Rate Limiting**: Going over `rate_limit.requests_per_minute` returns 429 with a `Retry-After` header giving the seconds to wait. Requests are counted per client IP before the key is checked, so wrong-key guesses are limited too. The counts are kept in memory **per process**: with several workers or replicas, each allows the full limit, and a restart resets them. Behind a reverse proxy every request may come from the proxy's IP unless uvicorn is told to trust forwarded headers. Use a shared limiter (e.g. at your proxy) if you need a global limit.
- **Model Exposure**: Be very careful about which models and fields you expose. By default, `autocrud` does not expose any of your models. You must explicitly whitelist them in your `autocrud.yml`. Avoid exposing sensitive data like user passwords or other personal identifiable information (PII). At startup, `autocrud` logs a warning for each exposed column whose name contains `password`, `passwd`, `secret`, `token`, `ssn`, `email` or `api_key`; remove such columns with `exclude_fields`.
- **Database Permissions**: For production environments, it is strongly recommended to use a database user with the least required privileges. For example, if you only need to expose `get` and `list` operations, use a database user with read-only access.
